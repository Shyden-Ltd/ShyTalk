## Operating rules (from shyden, standing)

1. **Address shyden by name.** Every reply opens with a hat tag and a greeting,
   and ends with a momentum sign-off plus a UTC ISO-8601 timestamp.
2. **Never stop mid-queue.** Do not end a turn to report progress, ask "shall I
   continue", or summarise. Stop only for a blocker that genuinely needs
   shyden's decision. This was corrected three separate times — it is the most
   expensive habit to relapse into.
3. **Zero defects, no deferrals.** A bug, warning, linter finding or security
   flag halts feature work and is fixed immediately. Never propose "backlog
   it", "later PR", or "ignore for now". Warnings are build errors.
4. **TDD is the contract.** Failing test → observe the failure → minimal code →
   green with zero warnings → refactor → record the lesson here.
5. **Concise updates.** Code, explanation, edge cases, next steps. No
   pleasantries, no recaps of what just happened.

**Tension to hold:** this repo's own process (`CLAUDE.md`) requires ONE story =
ONE PR, and the pre-merge gate REFUSES a PR that modifies a story still in
Draft. So "file a ticket" is the repo's mechanism for scope separation, not a
deferral — but the FIX still happens now, in its own PR, before moving on. Do
not use ticket-filing as a way to postpone.

## Testing rules

### A source-reading pin must read CODE, not text
Filter out comments **and imports** before asserting, and assert on a
syntactic form (`header(APP_CHECK_HEADER`) rather than a bare identifier.
Three separate near-misses in one story:
- deleting an entire `header(...)` call left a pin green — it matched the
  `import` line;
- twice a pin matched **its own KDoc** quoting the call it was checking.
A pin that cannot fail is decoration. Always mutate the code and watch it redden.

### Verify the mutant applied before trusting a green
`str.replace` / `sed` that matches nothing exits 0 and changes nothing. Assert
`count(old) == 1` **before** writing, and grep the file afterwards. A "passing
mutation" is far more often a broken harness than a real finding.

### Never run a formatter between two scripted edits
Prettier/ktlint reformat the text the second edit is matching on, so its
`replace` silently no-ops. Do all text surgery first, format once at the end.

### Test doubles only in unit locations
`tests/unit/**`, `*.unit.test.js`, non-instrumented Kotlin source sets. The
`no-new-stubs` pre-push ratchet enforces this and it is right. Prefer
**inducing** the real condition: e.g. `getIpGeo` returns `{}` for any non-IPv4
address before it makes an outbound call, so an IPv6 caller is a genuine,
deterministic, offline geo failure with no stub at all.

### Assert what the code actually claims
Two end-to-end tests in one story asserted behaviour the system deliberately
does not have — a route that uses the LIVE value being asked about a STORED
one, and a 403 from a route that is ban-exempt by design. Find the real
consumer and call it.

### Add a control alongside every positive assertion
"The ban matches" needs "and without the stored value it does not". "Absent
keys are omitted" needs "and a successful lookup still writes them all".
Otherwise a fix that does nothing, or does everything, passes identically.

## Git rules

### `git reset --hard` after a FAILED `git checkout` rewrites the wrong branch
Separate lines behave like `;`, not `&&`. A failed checkout leaves you on the
old branch and the reset destroys uncommitted work there. Use
`git merge --ff-only origin/<branch>`, which refuses instead of discarding, and
commit scratch notes before running any git plumbing.

### Never chain a gate and the action it gates with `;`
`pre-merge-check.sh N && gh pr merge N` — never `;`, which merges even when the
gate refuses.

### Stage by name, never `git add -A`
Worktrees carry their own `node_modules`.

## CI rules

### `gh pr checks --required` exit 0 is a FALSE pass early on
"PR Gate" registers late. The authoritative signal is
`mergeStateStatus == CLEAN`. `wait-pr-checks.sh` also exits 0 on OVERRUN —
read its output text, never just its exit code.

### A pipe swallows exit codes
`cmd | tail` reports `tail`'s status. Capture to a file and check `$?` on the
command itself.

### Measure before calling something environmental
"Environmental" is not a diagnosis. Two consecutive identical failures on the
same tip = reproducible. Two successes three hours earlier on the same
workflow = state changed, not code. Get the numbers before deciding.
